# В моем эксперименте Release оказался быстрее Debug примерно в 7 раз

* в Debug присутствуют инструкции nop, которых нет в Release;
Когда я открыл метод в режиме Debug, там было много непонятных строк с командой nop. В Release этих строк вообще нет. Я так понял, nop — это просто «пустая операция». Она нужна, чтобы отладчик мог останавливаться на каждой строчке. В Release она не нужна, поэтому её убрали.

* в Release уменьшилось количество промежуточных операций с локальными переменными;
В Debug программа сохраняет каждую переменную в отдельную ячейку памяти, чтобы в отладчике можно было посмотреть её значение. В Release компилятор умный: он понял, что промежуточные переменные не нужны, и сократил количество операций. Кода стало меньше.

* количество IL-инструкций в методе Add() изменилось с 11 до 4.

## Контрольные вопросы
* Что такое IL и зачем он нужен между C# и машинным кодом?
 IL — промежуточный код, в который компилируется C#. Он не привязан к конкретному процессору, а JIT при запуске переводит его в машинный код нужной архитектуры.

 * Почему .dll можно декомпилировать? 
 В .dll хранятся IL и метаданные (имена классов, методов, типов), поэтому по ним можно восстановить код, похожий на исходный.

 * Какие отличия Debug и Release вы увидели в IL? 
  В Debug есть `nop`, лишние локальные переменные (`.locals init`) и операции `stloc`/`ldloc`. В Release их нет, и IL короче.

  * Почему Release обычно быстрее Debug?
  В Release компилятор и JIT применяют оптимизации, а в Debug код оставлен удобным для отладки.

  * Почему строковый пароль в .dll нельзя считать защищённым?
Строки хранятся в .dll открытым текстом (UTF-16) без шифрования, и их видно в HEX-редакторе или ILSpy.
